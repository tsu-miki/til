# AI に実装を任せる前に、受け入れ条件を自分で書いておく

何ができていれば完成なのかを先に書き出しておくと、上がってきたコードを読みながら「まあ良さそう」で判断せずに済む。

```markdown
## 受け入れ条件: 期限切れトークンを弾く
- 期限切れトークンで /me を叩くと 401
- レスポンスに token 本体を含めない
- 既存の正常系テストはそのまま通る
```

条件が 3〜4 行で書ける大きさまで依頼を割り、渡すコンテキストもその範囲に絞る。条件を決めずに投げると、それらしい説明つきで「実装しました」と返ってきて、結局こちらが読み直すことになる。何をもって正しいとするかが仕様の中心にあるときは、テストは自分で書いて渡す。

参照: https://code.claude.com/docs/en/best-practices
