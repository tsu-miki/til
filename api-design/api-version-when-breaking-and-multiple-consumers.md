# API のバージョンを切るのは、破壊的変更かつ利用箇所が複数あるとき

バージョンを切る目的は旧仕様の利用側を壊さないことなので、破壊的変更であっても利用箇所が一つで自分たちが同時に直せるなら、バージョンは要らずそのまま変えればよい。

```http
# 破壊的変更 × 利用箇所が複数（一斉更新できない）→ 旧版を残す
GET /v1/users   # 既存の利用側はそのまま
GET /v2/users   # 移行先

# 破壊的変更 × 利用箇所が一つ（同時に直せる）→ そのまま変える
GET /users
```

判断の軸は「変更が破壊的か」だけではなく「利用側を自分たちで同時に更新できるか」。専用の BFF や単一クライアントなら後者に当たり、バージョンを切ると移行期間の二重実装だけが残る。

何が破壊的変更かは AIP-180 に整理がある（フィールドの削除・リネーム、必須化、既存フィールドの意味の変更など）。

参照: https://google.aip.dev/180
