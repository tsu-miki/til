# 一覧 API の安全な既定値は事故を防ぐが、アクセス制御にはならない

既定で安全な部分集合だけを返す一覧は標準化された設計だが、クエリパラメータを付ければ誰でも全件を取れるので、渡してはいけない相手を止める手段にはならない。

```http
GET /resources              # 既定はプライバシーポリシー適用後のみ
GET /resources?policy=all   # 誰でも付けられる。既定値は壁ではない
```

「一覧は全件」は慣習であって REST の要件ではない。AIP-164 もソフトデリートしたリソースを既定では返さないと定めている。既定を安全側に置くのは、取りこぼしは後から取り直せるのに対し、渡してしまった個人データは戻せないという非対称性があるから。真偽値の `include_xxx=true` より `policy=applied|all` のように取得範囲を名前で表すほうが、既定が何を指すか説明しやすい。

「うっかり混ぜてしまうのを防ぐ」なら既定値でよいが、「この利用者には渡してはいけない」なら認可で止める。Saltzer と Schroeder の fail-safe defaults は、アクセスを「拒否の条件」ではなく「許可の条件」で判断する原則で、既定値ではなく認可の話。GDPR 25 条 2 項も、既定と認可の両方を求めている。
