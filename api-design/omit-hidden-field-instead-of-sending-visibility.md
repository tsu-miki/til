# 表示可否が関連リソースで決まる項目は、判定材料ごと渡さずサーバ側で落とす

出すか出さないかが公開設定のような別リソースで決まる設計で、値と可否を両方返してクライアントに出し分けさせると、隠すはずの値はもう渡し終わっている。

```json
// NG: 出し分けはクライアント任せ。hidden でも phone の値は渡っている
{
  "id": 42,
  "name": "山田 太郎",
  "phone": "090-0000-0000",
  "visibility": { "phone": "hidden" }
}

// OK: 非公開ならキーごと返さない
{
  "id": 42,
  "name": "山田 太郎"
}
```

`"phone": null` でキーを残すと、値は隠せても「電話番号を登録しているが非公開」という事実は残る。それも隠したいならキーごと落とす。

代償はレスポンスの形がリクエストごとに変わること。スキーマ側で必須と任意を分けておく。渡してはいけない相手がいるなら、出し分けではなく認可で止める。
