# 別々にデプロイするサービス間では、破壊的変更を expand と contract に分ける

提供側と利用側を同時にデプロイできない以上、必須パラメータの追加のような破壊的変更は、各段が後方互換になる 3 段に分解するしかない。

```http
# 1. expand: 任意で受ける。未指定は従来どおりの挙動
POST /users                          # tenant_id は任意

# 2. migrate: 利用側が各自のタイミングで送り始める
POST /users {"tenant_id": "..."}

# 3. contract: 未指定が消えたのを確認してから 400 にする
```

3 に進む条件は「たぶん移行した」ではなく、未指定リクエストが呼び出し元ごとにゼロだと計測で確認できること。移行を促すなら未指定時に `Deprecation` / `Sunset` ヘッダを返す手もある。

未指定時の妥当なフォールバックが定義できないときは expand ができないので、バージョンを切る側の判断になる。

参照: https://martinfowler.com/bliki/ParallelChange.html
