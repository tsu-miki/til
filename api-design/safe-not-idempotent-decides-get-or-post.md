# GET か POST かは、冪等かどうかではなく、サーバの状態を変えるかで決まる

冪等性は PUT も DELETE も満たすので、GET を選ぶ理由にならない。分かれ目は「安全（safe）か」、つまりサーバの状態変更を要求しているかどうか。

```http
GET  /users/42   # 取得。状態を変えない = 安全
POST /users      # 作成。状態が増える = 安全でない
PUT  /users/42   # 冪等だが安全ではない。GET にはならない
```

RFC 9110 は安全を「意味論が実質的に読み取り専用」、冪等を「複数回送ったときのサーバへの意図した影響が 1 回分と同じ」と定義する。安全なメソッドは冪等でもあるので、安全性から決めればよい。

「何度呼んでも同じ結果が返る」は冪等性ではない。GET は他人の更新で毎回違う結果を返しうるが、それでも冪等。冪等性はレスポンスではなくサーバ側の影響の話。

参照: https://datatracker.ietf.org/doc/html/rfc9110#section-9.2
