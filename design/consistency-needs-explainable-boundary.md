# 中途半端な統一を避ける方法は、全部やることではなく境界を明示すること

一貫性は「全部揃っていること」ではなく「どこで分かれるかを一文で説明できること」で保たれるので、全体を寄せきれないときは境界を引いて内側だけ例外なく寄せる。

```markdown
<!-- README.md -->
## エラーハンドリングの移行方針

- `src/features/` 配下は Result 型で返す（移行済み）
- `src/legacy/` 配下は従来どおり例外を投げる
- 新規に追加するものは Result 型で書く
```

境界の候補はディレクトリ、レイヤー、「新規かどうか」という時間軸。引ける境界がない、あるいは内側を今回のスコープで寄せきれないなら、据え置いて既存の一貫性を優先する。方針を README か ADR に一行残すと、次に触る人が同じ判断をたどれる。

参照: https://martinfowler.com/bliki/StranglerFigApplication.html
