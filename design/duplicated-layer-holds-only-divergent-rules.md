# 利用者ごとに複製される層に置けるのは、コピーごとに答えが違ってよい判断だけ

BFF のようにクライアントごとに 1 つずつ用意する層は、増やした数だけ中身も複製されるので、どのコピーでも答えが揃っていないと困るルールを置くと、正が何本もできる。

```
# BFF は Web 用と iOS 用に 1 つずつ → 置いたものは 2 本に増える
Web BFF ─┐
         ├→ 注文サービス / クーポンサービス
iOS BFF ─┘

置ける : 一覧に画像 URL を含めるか（Web は含める、iOS は含めない）
         → コピーごとに違ってよい
置かない: クーポンを使えるか（合計 5000 円以上 かつ 期限内）
         → 2 本に書かれ、片方だけ改定されると答えが割れる
```

「BFF はロジックを持たない」と要約されがちだが、持たないのではなく、呼び出し順・詰め替え・片方が落ちたときの代替表示といった、そのクライアントのためだけの判断は BFF にしか置けない。分かれ目はロジックの種類の名前ではなく、コピーごとに答えが違ってよいかどうか。複製されない側に置けば、揃うことは構造で保証される。
