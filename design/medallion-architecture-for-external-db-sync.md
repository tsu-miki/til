# 取り込んだ生データは、変換後とは別に丸ごと残す

変換した結果しか持たないと、変換を直すたびに取り込み元へ取りに行くことになるので、受け取ったままの形の層を分けて置く。

```
外部 DB（ソースシステム。こちらからは変更しない）
  ↓ 取り込み
Bronze: 取り込んだままのスナップショット。外部のスキーマのまま
  ↓ クレンジング・重複排除・複数ソースの統合
Silver: 一貫したビュー。3NF や Data Vault で正規化した書き込み最適化の形
  ↓ 用途に合わせた変換
Gold: 非正規化した読み取り最適化の形。アプリはここを読む
```

この 3 層がメダリオンアーキテクチャ。Bronze を外部のスキーマのまま残せば、Silver 以降を作り直すのに再取り込みが要らない。

効くのは、取りに行き直せるとは限らないから。相手のデータは書き換わり、過去の状態は残っていないことが多い。再取得できない入力があるなら層を分ける、が判断の形で、外部 API のレスポンスやログの取り込みでも同じ。名前の順に正規化が進むわけではなく、正規化されるのは Silver、Gold はむしろ非正規化される側。
