# ルールをメソッドに切り出すと、そのルールを直す場所が 1 か所になる

処理のまとまりを名前つきのメソッドに独立させると、判断に使う値がその中だけに現れるので、ルールが変わったときに直すのはそのメソッドで済む。

```java
// before: 送料の判定が呼び出し側に埋まっている
int shippingCost = 0;
if( basePrice < 3000 )
    shippingCost = 500;

// after: 送料計算をメソッドに独立させる
int shippingCost = shippingCost(basePrice);

// メソッドに独立させた送料計算のロジック
int shippingCost(int basePrice) {
    if( basePrice < 3000 ) return 500;

    return 0;
}
```

3000 と 500 がメソッドの中にしか現れないので、呼び出し側は送料がいくらかを知らずに済む。残るのは、単価×数量 → 送料 → 税込という流れだけ。

切り出す単位は行数ではなく、一緒に変わる範囲。同じルールが何箇所かにあるなら、名前を先に決めてから寄せる。

参照: 増田亨『現場で役立つシステム設計の原則』第 1 章 https://gihyo.jp/book/2017/978-4-7741-9087-7
